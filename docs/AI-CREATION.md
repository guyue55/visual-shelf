# 可复用的 AI 辅助创作流程

调研及更新：2026-11-16。目标：让用户提供“给某产品做一张某主题的封面”这样的短指令，AI 复用已有品牌、参考和制作规则，只确认真正缺失的关键项。本文是本项目的制作协议与实施方案，不代表已接入生成模型或自动执行管线。

## 1. 调研发现与取舍

| 一手来源 | 已核实的机制 | 对本项目的启发（项目决定） |
| --- | --- | --- |
| [Canva：品牌模板与品牌资料生成](https://www.canva.com/help/create-on-brand-designs/) | 将品牌模板加入 Brand Kit，可为 AI 提供品牌与版式上下文；文档建议清晰占位文字、参考图及结构化布局。适用账号与设计类型有限，网页提取品牌信息也只是尽力而为 | 保存品牌事实和场景模板，不只保存提示词；不能承诺免费个人账号具备同等功能 |
| [Canva：模板发布](https://www.canva.com/help/publish-team-template/) | 锁定关键 Logo、必需文案与布局，修改草稿与已发布模板分开 | 指定固定区域与可变量，候选方案不覆盖已确认品牌 |
| [Adobe Express：品牌资料](https://www.adobe.com/us/learn/express/web/create-brand-kit) | 可组织并复用 Logo、颜色、字体、图形和模板；教程发布日期为 2024-04-30 | 品牌档案要保存明确值与文件引用，减少反复解释配色和字体 |
| [Adobe Firefly：文字生成矢量](https://helpx.adobe.com/firefly/web/generate-vectors/text-to-vector/generate-vectors-using-text-prompts.html) | 文档说明可加入风格参考图并导出可编辑 SVG；具体设置依模型而异 | 需要可编辑路径的 Logo/图标可以走矢量路线，输出仍须经本地 SVG 校验和视觉检查 |
| [Recraft Styles](https://www.recraft.ai/v4styles) 及其链接的 [API 快速入口](https://www.recraft.ai/docs/api-reference/getting-started) | 官方提供参考图驱动的风格控制和 API 入口 | 参考图应随品牌持久保存；作为未来候选，不依据厂商宣传认定质量胜出，也不绑定其服务 |
| [DTCG Design Tokens 2025.10](https://www.designtokens.org/tr/2025.10/format/) | 提供颜色、尺寸、字体等设计值的跨工具交换格式；属于社区规范，不是 W3C 标准 | 先保存可读的颜色、字体、留白等值，后续有真实工具互通需求再接入 tokens；本期不声称符合完整规范 |

推导：减少重复沟通依赖“已确认资料 + 可复用制作流程 + 本次变化 + 结果反馈”，不能靠更长的一段固定提示词解决。风格参考用于指导，不能保证每次生成结果完全一致。

本轮来源状态均为 found（可读取的官方页面）；未实际登录 Canva/Adobe/Recraft 测试，不核算套餐价格、不比较模型排名、不声称已完成 API 集成。生成质量、中文排字、成本和本地 SVG 白名单兼容性均需真实样本验证。

## 2. 上下文分层与文件位置

| 层次 | 保存内容 | 维护位置 |
| --- | --- | --- |
| 全库规则 | 协作与素材管理要求 | AGENTS.md、ASSET-MANAGEMENT.md |
| 项目/产品事实 | 名称、实体关系、家族、推荐素材、使用记录 | 实体登记卡 |
| 品牌档案 | 色彩字体、固定元素、认可/否决参考、风格与例外 | 每实体独立品牌档案 |
| 场景制作流程 | Logo、封面、图例的步骤、变量与验收 | [CREATION-RECIPES.md](CREATION-RECIPES.md) |
| 本次任务 | 主题、文字、用途、输出范围和临时覆盖项 | [任务简报模板](../templates/creation-brief.md) |
| 制作记录 | 实际输入、工具/模型、候选、选择、编辑和验证 | [制作记录模板](../templates/creation-run.md) |

首次需要时复制 [品牌档案模板](../templates/brand-profile.md)，保存为 `docs/brands/products/<slug>.md` 或 `docs/brands/projects/<slug>.md`，由实体登记卡链接。shared 可按真实需要创建 `docs/brands/shared.md`；不自动给所有产品统一风格。

制作记录按 `docs/creation-runs/<YYYY-MM-DD>-<entity-type>-<slug>-<task-slug>.md` 保存，同日重名加序号。此处只存可公开的过程与文件引用；大量候选图、敏感资料和设计工程保存到用户指定的工作位置，成品再经 add 导入。Markdown 不随当前站点构建分发，但一旦推送公共仓库仍然公开。

实体名称、推荐 asset id 以登记卡为准，品牌档案不复制一份同样的表；档案引用 catalog id 与真实参考文件。参考文件未在运行工具中实际加载，不能声称“已参考”。外部参考用链接与可用文件位置记录，不伪造缺失图片。

## 3. 首次与后续交互

### 首次为某实体建立视觉方向

1. 先读取登记卡、已有 Logo、封面及 README 等现成信息，列出已知内容，不让用户重新填写已有事实。
2. 只询问会阻塞结果的缺口，例如到底是哪一个产品、Logo 必须出现的准确文字。把相关问题合并为一次简短询问。
3. 其余如未知风格和配色，可提出 2～3 个有区别的探索方向；记录为候选或假设，不能当成用户长期偏好。
4. 明确“本次尝试”和“已确认品牌规则”。用户选中方向后，把其选择、范围和日期写入对应品牌档案，保留关键否决理由。

### 已有品牌档案后的制作

先读档案、认可参考、对应制作流程与相关历史记录。用户通常只需给“实体 + 用途 + 主题/本次变化”。颜色、字体、固定 Logo、已认可风格等不重复追问。

- 优先使用当前指令；本次要求与档案不同通常视为单次覆盖，不自动重写长期品牌规则。
- 覆盖固定 Logo 或产生实质品牌改版时明确说明影响；无法判断是否改版且影响结果时再确认。
- 场景流程缺省值用于补足非关键空白，并在简报中说明。品牌禁止项优先于普通模板默认值；本次明确要求改变时按本次范围执行。
- 没有档案时不冒充已经知道用户喜好；资料足够仍可以先做探索稿。
- 默认不要为了“确认已经确认的信息”中断；用户请求创作通常授权制作本地候选稿，不自动授权公开发布或新增付费订阅。

## 4. 制作路线

| 需求 | 优先路线 | 关键约束 |
| --- | --- | --- |
| 已有 Logo 的封面/适配 | 复用真实 Logo 原文件 + 可编辑排版，必要时生成背景 | 不让生成模型重画固定标识；标题、署名等准确文字单独排版 |
| 新原创 Logo | 概念探索 → 选定方向 → 矢量细化 → 尺寸/配色适配 | 位图概念不当作可编辑矢量终稿；不把 PNG 改扩展名冒充 SVG |
| 规则清晰的几何 Logo/图例 | 手工/程序矢量或设计工具 | 以视觉验收为准，不能以“SVG 能解析”证明图形正确 |
| 插画或照片风格封面 | 可用生成工具产出主体/背景，再复用品牌排版 | 有参考时实际附图，保留文字区与裁切安全区域 |
| 连续系列内容 | 使用同一品牌档案、版式、参考与设计值，只替换主题变量 | 版本固定，避免每张独立重新设计；多尺寸应重新排版而非盲目裁切 |

当前仓库的 `create` 只提供有限 SVG 模板（封面、状态图例、完成标记），不是上述全部路线的实现。AI 助手可使用当次可用且获授权的图像/设计工具；没有工具时完成简报和提示词，并明确尚未出图。接入外部服务前按当次授权核对费用与素材传输范围，不自行创建账号或长期保存凭据。

实际生成参数按当前工具文档核对，不向不支持的模型硬塞 seed、negative prompt、SVG 或透明背景参数。记录可用的真实模型标识，不猜测供应商后端版本；只有工具支持时才记录 seed。相同提示词或 seed 不作为跨模型、跨版本完全复现的保证。

## 5. 提示词组装与局部迭代

每次根据资料组装，而不是让用户重写：

```text
任务：<实体、素材类别、用途、新建/适配/修改>
品牌依据：<档案路径/修订、已确认规则、实际加载参考>
不可改项：<现有 Logo、准确文字、指定颜色、必须保留元素>
本次变化：<主题、内容、尺寸、临时风格要求>
构图与输出：<比例、主体、文字安全区、背景/透明、可编辑要求>
避免事项：<档案中具体的否决项，不套用泛泛禁令>
验收：<按制作流程列出可检查条件>
```

修改时保留“已接受的基准文件 + 明确差异”，只改变用户提出的部分。候选用稳定编号 A/B/C 或 run id，避免用户说“上一张”时无法定位。用户选择只更新对应实体的规则或推荐项，不传播到别的产品，也不写入工具全局记忆。

最终记录实际提示词、参考顺序、工具参数、人工编辑和文件位置。未选中方向记录必要的原因，不保留大量无用聊天副本。提示词、参考和运行记录可追溯，但不保证生成结果完全可复现。

## 6. 验收与入库

- Logo：小尺寸辨识、单色版、浅/深底、比例留白、准确字标，矢量路径与字体依赖检查。
- 封面：标题准确、层级与留白、真实 Logo 未变形、目标比例和裁切；多语言换行单独检查。
- 图例：线宽/形状一致、说明与图形对应、常用缩放下可读。
- 按实际工具保存可编辑源与引用，明确哪些仅为位图。字体未嵌入/未转路径时记录依赖，不承诺跨设备完全相同。
- 按素材管理规范决定 family/variant/revision，使用 add 登记成品，更新卡片推荐项及真实 usage；检查 validate/build 与实际预览。
- 接受结果不等于通过商标检索或开放授权；来源与权利仍依 RIGHTS.md 逐项记录。

## 7. 实施优先级与验收场景

现在即可由能读仓库的 AI 按本协议执行：查档案 → 补变化 → 调用当次可用工具 → 验收 → 记录与入库。已有文档不是自动加载或工具执行成功的证据。

后续优先实现：品牌档案与任务简报的结构化校验、提示词/参考上下文导出、可编辑排版模板和成品登记。再按实际需要加入模型适配、批量尺寸导出和创作页面。供应商选择通过同一批任务实测，比较接受率、修改轮次、中文准确性、文件可编辑性和真实成本，不按宣传排名决定。

建议用以下真实场景验收，当前尚未执行：

1. 同一产品连续做两张不同主题封面，第二次不再询问已知品牌配色与字体。
2. 另一产品明确使用不同风格，不能继承前一个产品的参考和禁止项。
3. 已有 Logo 只调整封面布局，Logo 文件保持原样。
4. 用户否决“发光效果”，下次同范围创作自动避开；单次节日风格不覆盖长期规则。
5. 新会话只给实体和用途，AI 可找到正确档案、参考和制作流程；必要文件缺失时如实说明。

统计制作记录时可汇总任务数、候选数、修改轮次、首次沟通后的重复品牌提问次数、用户接受的成品数，以及有真实账单证据的费用。探索候选不计入成品库文件数，也不把“未反馈”当成“已接受”。
